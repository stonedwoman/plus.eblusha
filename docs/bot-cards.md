Решения владельца 2026-10-11. Сервер: `src/lib/botCards.ts` (общий конверт), `src/lib/promiseTimer.ts` +
`src/lib/promiseTime.ts` + `src/lib/promiseTexts.ts` (таймер), `src/lib/botShare.ts` (переписка),
`src/routes/cards.ts` (клиентам), `src/routes/botCards.ts` (боту), `src/jobs/workers/cards.worker.ts` (очередь
`cards`). Сервис бота: `bot/src/core/{promises,share,cardIntents,promiseTime}.ts`, `bot/src/core/bot.ts`
(`handleCards`, `handleDeep`), `bot/src/modules/valheim/promiseWatch.ts`. Общий контракт бота — `docs/bot-system.md`
(ревизия задачи 4). Клиенты: веб, ПК-натив (главный), Android, iOS — все четыре.

Общие векторы клиентов: `docs/bot-card-vectors.json` (конверт, права, `rev`), `docs/promise-card-vectors.json`
(вид таймера), `docs/share-card-vectors.json` (вид «поделиться»); разбор времени — `test/fixtures/promise-time-vectors.json`.

## 1. Общий конверт (Bot Cards v1)

Карточка — обычное сообщение бота (`message.isBot === true`), чьё состояние меняет ТОЛЬКО сервер:

```jsonc
{
  "bot":  { "v": 1, "kind": "card", "triggerMessageId": "…", "askerId": "…" },
  "card": {
    "v": 1,                          // клиент рисует только v === 1
    "type": "promise" | "share",     // неизвестный тип → запасной текст content
    "id": "…",                       // PromiseTimer.id / BotShare.id (для журналов)
    "rev": 3,                        // растёт при каждой смене; принимать только rev > своего
    "state": "…",                    // словарь типа (§2.2, §3.3)
    "closed": false,                 // финал: действий нет, кроме действий с until («Вернуть»)
    "actions": [ { "id": "arrived", "who": { "any": true }, "until": null },
                 { "id": "cancel",  "who": { "ids": ["…"] }, "until": null } ],
    "data": { … }                    // данные типа
  }
}
```

- Рисовать карточку, только если `isBot === true` (или `sender.isBot`), `metadata.bot.kind === "card"`,
  `metadata.card.v === 1` и тип известен. Иначе — обычный пузырь бота с `content`.
- `who`: `{any: true}` — любой участник беседы; `{ids: […]}` — перечисленные. `until` — ISO (или `null`): после
  него клиент прячет действие сам, без события. У `closed` — только действия с `until`.
- `content` — запасной текст (старые клиенты, превью, поиск, пересылка). Сервер переписывает его при каждой смене
  (без `editedAt`, пометки «изменено» нет). Время в нём — по Москве с «МСК».
- Ключи `card` и `promise` — служебные: у сообщений людей сервер их вырезает (как `bot`, `isBot`, `botAsk`).
- reply-шапка: у таймера НЕ рисовать (карточка сама показывает «попросил Рома» и цитату обещания); у «поделиться» —
  оставить (это ответ на вопрос). «Уточнить» и «Подумай лучше» под карточками не показывать.
- «Удалить» — как у ответа бота (`metadata.bot.askerId` = я). Удаление карточки = отмена таймера / «забыть переписку».

### 1.1 Маршруты клиентам

```
GET  /api/cards/:messageId                        → 200 { message, card, serverNow }
POST /api/cards/:messageId/act { action, input? } → 200 { message, card, serverNow }
```

Ошибки — `{ message, code, card?, serverNow }`:

| Код | Когда | Клиент |
|---|---|---|
| 404 `CARD_NOT_FOUND` | нет карточки / не участник / секретная беседа | убрать оптимистичное, молча |
| 400 `CARD_BAD_INPUT` | `input` не по схеме типа (в т. ч. недоступный период) | тост «Не получилось» |
| 403 `CARD_FORBIDDEN` | `who` не выполнено | тост по типу («Решает тот, кто спросил») |
| 409 `CARD_CLOSED` `{card}` | состояние уже не позволяет | молча перерисовать по `card` |
| 409 `CARD_ACTION_EXPIRED` `{card}` | `until` прошёл | молча перерисовать |
| 404 `CARD_TYPE_DISABLED` | тип выключен (`BOT_SHARE=off`) | тост «Сейчас недоступно» |
| 429 `RATE_LIMITED` | ≤ 30 действий в минуту | тост «Слишком часто» |

Права решает сервер под замком строки типа (`SELECT … FOR UPDATE`): две кнопки сразу — второй получает 409 с
итогом первого.

### 1.2 Событие

```
message:update { conversationId, messageId, reason: "card", cardType: "promise" | "share",
                 message, card, serverNow }
```

В комнату беседы, после фиксации каждой смены (кнопки, звонок, бот, очередь сроков). Новые клиенты заменяют
сообщение на месте (не перечитывая ленту), берут `serverNow` в смещение часов (медиана трёх, применять при
|смещение| > 2 с); карточки нет в загруженном окне — ничего. Событий «раз в секунду» нет: секунды и минуты клиент
считает сам от данных. Мост из воркера (`realtime:message:update`) теперь передаёт `cardType`, `card`, `serverNow`.
Старые клиенты: веб заменит сообщение (новый `content`), натив/Android/iOS перечитают ленту.

## 2. Таймер обещания («Еблуша, проконтролируй»)

### 2.1 Как ставится

- **Ответом на обещание** (главный путь): Вася — «15мин»; Рома отвечает на это сообщение «Еблуша, проконтролируй»
  (или «засеки», «следи», «запомни»). Карточка — ответом на обращение Ромы.
- **Без ответа**: бот берёт у сервера кандидатов — сообщения ДРУГИХ участников за час до обращения, которые
  разборщик признал обещанием времени (остальная переписка боту не отдаётся). Один человек — он; несколько —
  «Кого контролируем? 1. … 2. …» (ответ номером или именем).
- **О себе**: «Еблуша, я буду через 15 минут, засеки», «Еблуша, засеки 15 минут».
- **Про другого словами**: «Еблуша, проследи, чтобы Вася был к девяти» — модель (инструмент `promise_timer`),
  цитата — слова спросившего, на карточке «со слов: Рома».
- Время понимает СЕРВЕР (`src/lib/promiseTime.ts`): «15мин», «через полчаса», «час-полтора» (верхняя граница:
  метка «час-полтора → 1,5 ч»), «в два часа давай» (ближайшее будущее 02:00/14:00 от времени обещания; дальше 8 ч —
  переспрос «Это 02:00 ночи?»), «к 9», «в 21:30», «без четверти три», «завтра в 2» — в МЕСТНОМ поясе автора
  обещания (Redis `ltz:eff`; «по мск» в тексте сильнее). База — время сообщения-обещания. Срок ∈ [сейчас − 60 мин;
  база + 36 ч]: в прошлом в пределах часа — карточка сразу «опаздывает». Не понял — бот зовёт модель (она
  возвращает только структуру, срок всё равно считает сервер), потом переспрашивает «во сколько?».
- Уже в звонке этой беседы / уже в Valheim (вошёл после обещания) — «засекать нечего», карточки нет.
- Пределы: ≤ 3 идущих на беседу, ≤ 1 на (беседа, обещавший), ≤ 10 в сутки на спросившего (не владельца бота),
  ≤ 10 продлений, ≤ 5 напоминаний. Выключатель — `PROMISE_TIMERS=off` (бот: «Таймеры пока выключены»; закрыть идущие
  кнопками можно).

### 2.2 Данные карточки (`card.type = "promise"`)

```jsonc
{
  "state": "running" | "arrived" | "cancelled" | "unresolved",
  "actions": [ /* running: */ { "id": "arrived", "who": { "any": true }, "until": null },
                              { "id": "cancel", "who": { "ids": ["<спросивший>", "<владелец бота>"] }, "until": null },
               /* 2 мин после ручного закрытия: */ { "id": "reopen", "who": { "ids": [...] }, "until": "ISO" } ],
  "data": {
    "promiser":  { "id", "displayName", "avatarUrl" },      // имя/аватар брать из своего кэша, это — запасные
    "requester": { "id", "displayName" },
    "quote": { "messageId", "text" | null, "at", "by": { "id", "displayName" } | null, "deleted": false },
    "label": "15 мин",                 // «в 14:00», «час-полтора → 1,5 ч», «завтра в 14:00» — в поясе обещавшего
    "upperBound": false,
    "startAt": "ISO", "deadlineAt": "ISO", "originalDeadlineAt": "ISO",
    "extensions": [ { "at", "from", "to", "label" } ], "extensionCount": 0,
    "promiserZone": "Asia/Krasnoyarsk" | null,  // только если обещавший сам показывает местное время
    "cancelBy": ["…"],
    "closedAt": "ISO" | null,
    "outcome": { "kind": "onTime" | "late", "arrivedAt", "deltaSec", "deltaVsOriginalSec",
                 "via": "button" | "self" | "call" | "valheim" | "phrase", "by": { "id", "displayName" } | null } | null,
    "cancelledBy": { "id", "displayName" } | null,
    "reopen": { "until", "by": [...] } | null,   // дублирует действие reopen (для подписи)
    "reminders": [0, 15]                          // по каким смещениям бот уже напомнил
  }
}
```

Вид на клиенте (`now` = часы сервера): running & до срока > 60 с — «идёт»; ≤ 60 с — «последняя минута»; после срока —
«опаздывает» (+мм:сс вверх); arrived — `outcome.kind` вовремя/опоздал; cancelled; unresolved («никто не отметил»).

Действия (`POST /api/cards/:id/act`): `arrived` (любой участник; сам обещавший → `via: "self"`), `cancel`
(спросивший и владелец бота), `reopen` (2 минуты после ручного «Пришёл»/«Отменить» — тому, кто закрыл, спросившему и
владельцу; авто-закрытия «Вернуть» не дают). «Вернуть» проверяет те же пределы, что создание: тому же человеку уже
поставили новый таймер — 409 `PROMISE_EXISTS`, в беседе уже три — 409 `PROMISE_LIMIT`, он уже в звонке этой беседы —
409 `PROMISE_ALREADY_HERE` (во всех случаях с текущей карточкой: клиент молча перерисовывает).

Срок и пояс (ревью 2026-10-11): относительное время — от сообщения, где сказаны СЛОВА времени (обычно само обещание;
ответ на «Когда он будет?» / «Это 02:00 ночи?» и обращение «проследи, чтобы Вася был к девяти» — бот передаёт его как
`textMessageId`), а начало таймера (кольцо, «пришёл не раньше обещания») — время обещания. Пояс — автора слов: «к 9»
обещавшего — его пояс, «к 21:30» спросившего — пояс спросившего; продление — пояс обещавшего, поправка — спросившего.
Однозначное время, прошедшее не больше 30 мин назад («в 14 буду» в 14:02), — «опаздывает», а не завтра; ночью (до
5 утра) «завтра» — наступивший день («после сна»); «в 5 минутах» — через 5 минут, «в 3 раза», «в 2 км», «в двух
шагах» — не время; «через 1:30» — длительность.

### 2.3 Само закрывается и напоминает

- Обещавший вошёл в звонок ЭТОЙ беседы: сокет `call:invite` (сам позвонил), `call:accept`, `call:room:join` и
  вебхук LiveKit `participant_joined` (комната `conv-<id>`) — «пришёл», `via: "call"`; первый выигрывает.
- Вошёл в Valheim (персонаж привязан к нему в боте) — бот видит вход по `since` мода и отмечает `via: "valheim"`.
- Фраза «Еблуша, пришёл / он тут / я тут / стоп» (ответом на карточку или напоминание, или при единственном
  таймере) — `via: "phrase"` (сам обещавший — `self`); время прихода — время ЭТОГО сообщения (не момент, когда бот
  до него дошёл). Вход в Valheim, отметка которого сорвалась из-за сбоя сети или перезапуска сервера, бот повторит.
- «ещё 10 минут» / «+10» / «буду в 15:00» — продление, только сам обещавший (ответом на карточку/напоминание или
  «Еблуша, …» при его единственном таймере). Бот ставит 👍; карточка — «продлевал N раз», итог считает опоздание от
  последнего срока и отдельно от первого. Новое обещание самого обещавшего, на которое ответили «проконтролируй», —
  тоже продление: `POST /api/bot/promises/:id/extend {grant, sourceMessageId}` берёт слова из того сообщения.
- «не 2 ночи, а к 14» / «нет, к 14» спросившего ответом на карточку (первые 5 минут) — поправка срока
  (`/correct`), 👍.
- Напоминания — сервер от имени бота (`kind: "notice"`, `metadata.bot.promiseId`, `metadata.bot.mentions:
  [обещавший]` — задел под @): в срок, +15, +30 мин, весёлыми шаблонами без грубостей, ответом на сообщение-обещание
  (так оно пробивает «Без звука» обещавшего в группе по правилу мьюта «ответ на моё сообщение»), если его нет —
  на карточку. Таймер, созданный уже опоздавшим, «время вышло» не пишет; напоминание, опоздавшее больше чем на 5 мин
  (или когда уже настал срок следующего), — только отметка: «+15» и «+30» не приходят пачкой.
- Срок + 6 ч, никто не отметил — `unresolved` (в статистике отдельно, не опоздание).
- Очередь `cards` (BullMQ, Redis backend) — отложенные задачи переживают перезапуск; `sweep` раз в 5 мин догоняет
  потерянное (напоминание с опозданием > 5 мин не шлётся — только отмечается).
- Удалили карточку — таймер отменён; удалили обещание — цитата «(сообщение удалено)», таймер идёт; поправили обещание —
  цитата поправлена; обещавший вышел из беседы — отменён (`cancelledBy: null`, `closeReason: promiser_left` — не
  «отменил Вася»).

### 2.4 Запасной текст

| Состояние | `content` |
|---|---|
| идёт | `⏱ Таймер: **Вася** обещал «15мин» — жду до 14:15 МСК.`⏎`Живой таймер — в новой версии Еблуши.` |

### 2.5 Пунктуальность

«Еблуша, как у Васи с пунктуальностью?», «Вася часто опаздывает?», «кто самый пунктуальный?» — по таблице
`PromiseTimer` на сервере (исходы случаются там), только по беседам, где спрашивающий участник И где есть все люди
беседы, в которой прозвучит ответ (таймеры из лички Ромы с Васей не видит Петя в их общей группе): обещаний, вовремя
из скольких (%), среднее опоздание, рекорд с датой, лучшее, продления. Ответ — шаблоном, `kind: "command"` (под ним
нет «Подумай лучше»).

## 3. «Поделиться перепиской»

### 3.1 Когда бот просит

В обычной беседе (личка двух людей, группа) бот видит только обращения к себе и свои ответы. Нужна переписка людей
(«о чём мы тут договорились?», «что Вася говорил про субботу?», «подведи итог дня») — модель зовёт `read_chat`, и
вместо выдумки появляется карточка. В «Чате с Еблушей» карточки нет (бот видит весь чат), в секретных — бота нет.
Уточнения ответом по цепочке к ответу по переписке читают переписку без новой карточки, пока окно открыто.
Отказ («Не делиться») помнится 30 минут — бот не пристаёт к тому же человеку в этой беседе.

### 3.2 Данные карточки (`card.type = "share"`)

```jsonc
{
  "state": "pending" | "granted" | "declined" | "expired" | "revoked" | "ended",
  "actions": [ /* pending: */ { "id": "share", "who": { "ids": ["<спросивший>"] }, "until": "+30 мин" },
                              { "id": "decline", "who": { "ids": ["<спросивший>"] }, "until": "+30 мин" },
               /* granted: */ { "id": "forget", "who": { "any": true }, "until": "<конец окна>" } ],
  "data": {
    "asker":   { "id", "displayName" },
    "suggest": { "period": "today" | "week" | "all", "photos": false },  // photos — ВСЕГДА false: галку включает человек
    "options": [ { "period": "today", "messages": 34, "photos": 3, "photosUsed": 3, "enabled": true, "off": null, "capped": false }, … ],
    "note": null | "too_big" | "budget",       // бот вернул карточку: выбранный период неподъёмен
    "choice": { "period", "photos", "by": { "id", "displayName" }, "at" } | null,
    "until": "ISO" | null,                       // конец окна доступа (granted)
    "answerMessageId": "…" | null,               // первый ответ по согласию — «Ответ ниже ↓»
    "read": { "messages": 34, "photos": 3 } | null,
    "endedBy": { "reason": "declined|expired|question_deleted|asker_left|replaced|revoked|ended", "by": {…} | null, "at" } | null
  }
}
```

Действия: `share` `{ input: { period, photos } }` (спросивший, вариант включён и не пустой; фото — только если они
есть), `decline` (спросивший), `forget` (любой участник). Будит карточка только спросившего: пуш — только ему, а
`message:notify` остальным приходит с `muted: true` (тот же признак, что у «Без звука»: не звенеть, без плашки).
Галка «Включать фото» по умолчанию выключена всегда, даже если модель просила фото (`suggest.photos` — всегда false).

Периоды — по поясу спросившего: «Сегодня» — с 05:00 (до 5 утра — со вчерашних 05:00), «Эта неделя» — с понедельника
05:00, «Всё время» — с начала (больше 30 000 сообщений — последние 30 000). Граница фиксируется в момент выбора,
конец — «живой» до конца окна. Окно доступа — 60 минут, ожидание выбора — 30 минут.

### 3.3 Запасной текст и ответ текстом

| Состояние | `content` |
|---|---|
| ожидает | `🔒 Чтобы ответить, мне нужно почитать переписку этой беседы. **Рома**, поделиться?`⏎`Ответь на это сообщение: «сегодня», «неделя» или «всё время» (можно добавить «с фото») — или «не надо».` |
| неподъёмно | `🔒 Переписки выходит слишком много для моего лимита. **Рома**, выбери период поменьше: ответь «сегодня» или «неделя».` |
| дано, читаю / ответ есть | `🔒 **Рома** поделился перепиской за сегодня, с фото. Читаю…` / `… Доступ до 15:12 МСК.` |
| закончилось | `🔒 **Рома** делился перепиской за сегодня, с фото. Доступ закончился в 15:12 МСК.` |
| отказ / истекло | `🔒 **Рома** не стал делиться перепиской.` / `🔒 **Рома** не ответил — переписку не читаю.` / `🔒 Вопрос удалили — переписку не читаю.` / `🔒 Вопрос сменился — по этой карточке переписку не читаю.` / `🔒 **Рома** вышел из беседы — переписку не читаю.` |
| отозвано | `🔒 Переписка забыта · попросил **Петя**.` / `🔒 **Рома** забрал разрешение.` |

Старые клиенты отвечают на карточку текстом («сегодня с фото», «за неделю», «всё время», «не надо») — бот поймёт
(решает только спросивший). «Еблуша, забудь переписку» — любой участник, закрывает все согласия беседы.

### 3.4 Что читает бот и что хранится

- Только эта беседа, только период, без удалённых, истёкших и `SYSTEM`; фото — только с галкой, не больше 60
  самых новых (серверные превью ≤ 720×1280). Цитата сообщения ВНЕ периода (ответ на давнее) — без текста, только
  имя. Пока окно открыто, удаления и правки пишутся в Redis `share:chg:<беседа>` — бот выкидывает удалённое и
  перечитывает поправленное; удалили прочитанное, пока модель писала ответ, — ответ не публикуется.
- До 100 тыс. токенов — вся переписка перед вопросом (Opus 5.5, кэш 5 мин); больше — куски по 60 тыс. → заметки
  недорогой моделью (Haiku 5.5) с учётом вопроса + последние ≈ 15 тыс. токенов дословно. Фото — описания Haiku,
  до 4 фото «глазами» основной модели (`view_photo`).
- Ответ по переписке — без поиска и чтения страниц, без меняющих инструментов и без скачивания картинок по адресам
  из текста ответа: подложенная в чат фраза ничего не сделает от имени спросившего и не унесёт выдержку в адресе.
  Имена, цитаты, имена файлов, описания фото внутри `<chat_transcript>` обезврежены (обёртку не закрыть).
- Расход — в бюджет бота на спросившего; дороже `BOT_SHARE_MAX_USD` или остатка лимитов — вариант погашен заранее
  («слишком много» / «лимит на сегодня»), а если выяснилось после чтения — бот возвращает карточку к выбору
  (`POST /api/bot/share/:id/reopen`) и забывает прочитанное; новый выбор той же карточки — новая задача
  (`jobId share-<id>-<rev>`), бот читает новый период с начала.
- Сырая переписка, описания фото и заметки — только в памяти процесса бота до конца окна/отзыва (сервер шлёт боту
  сигнал «стереть», в том числе при удалении беседы; кэш бота и сам убирает просроченное раз в минуту), на диск не
  пишутся. 10 ответов по одному согласию — предел: бот честно просит спросить заново. На сервере — `BotShare` (кто, когда, период, счётчики, статус), без
  текстов. В постоянную память бота идут только его ответы, карточки согласия — нет.
- Выключатель — `BOT_SHARE=off` (бот: «Чтение переписки сейчас выключено»).

## 4. «Подумай лучше»

- Кнопка рядом с «Уточнить» (те же правила показа: под последней частью ответа, не под карточками и «да/нет»;
  значок мозга/искры). Нажатие СРАЗУ отправляет ответ (reply) на это сообщение бота с текстом «Еблуша, подумай
  лучше» (в «Чате с Еблушей» — «Подумай лучше»). Отдельного API нет.
- Не показывать под ответом с `metadata.bot.depth === "deep"` (уже «подумал лучше») и под ответом, на который я уже
  попросил «подумай лучше» (есть мой ответ на него с этим текстом) — бот повтор над тем же ответом всё равно
  отклонит («уже подумал»), но лимит и деньги не должны уходить на двойное нажатие.
- Бот понимает и словами: «подумай лучше / подумай ещё / подумай как следует / глубже» — ответом на свой ответ или
  без ответа (последний его ответ этому человеку в беседе). Берёт исходный вопрос с контекстом и отвечает заново
  самой мощной моделью (`claude-fable-5-1`, усилие high; недоступна — `claude-opus-5-5`, усилие max), с теми же
  инструментами (поиск, чтение страниц, Valheim). Коротко говорит, что изменилось против прошлого ответа.
  Над ответом по переписке — перечитывает переписку (пока доступ открыт; закончился — честный отказ без расхода),
  без поиска. Не думает над служебными ответами (`notice`, `command`, карточки, «да/нет»), над уже глубоким и над
  тем, над чем уже думал (в том числе «подумай ещё» без ответа, если последний ответ этому человеку — глубокий).
  Отказ глубокой модели — служебным сообщением без `depth` (обычный ответ в силе, просить можно снова).
- Ответ: `metadata.bot = { kind: "answer", depth: "deep", model: "<модель>" }`; первая строка текста —
  «🧠 **Подумал лучше**» (её видят и старые клиенты; клиент, рисующий метку по `depth`, первую строку с меткой
  может не показывать, чтобы не дублировать).
- Пределы (`.env.bot`): `BOT_DEEP_USER_DAILY=5` (владельцу `BOT_DEEP_OWNER_DAILY=20`), `BOT_DEEP_MAX_USD_PER_ANSWER=2`
  (жёстко: `max_tokens` КАЖДОГО шага урезается под остаток — весь вывод шага влезает в потолок; запасная модель
  получает остаток, а не новый потолок), `BOT_DEEP_MONTHLY_USD=40` (внутри `BOT_MONTHLY_BUDGET_USD`; следующий ответ
  не начинается, если месячный предел не выдержит его потолка). Просьбы, которые ещё думаются, бронируют место в
  дневном и месячном лимитах (параллельные просьбы из разных бесед не проходят разом); неудачный прогон (обрыв,
  перегрузка) тоже идёт в учёт. До 12 минут на ответ (не дольше жизни разрешения).
  Исчерпано — вежливо и когда обновится; обычный ответ остаётся. Проба модели при старте бота — `llm.deep_probe`.
