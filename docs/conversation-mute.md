# «Без звука» для бесед — контракт сервера для клиентов (v1)

Задача владельца 2026-10-11: «мьютить любые беседы, особенно групповые». Сервер: `src/lib/conversationMute.ts`
(хранение, события, фильтр пушей), `src/lib/conversationMuteRules.ts` (чистые правила — их повторяют клиенты),
`src/routes/conversations.ts` (`POST /:id/mute`, поля списка), `src/push/badge.ts` (значок iOS).
Клиенты: веб, ПК-натив (главный), Android, iOS — все четыре. Electron заморожен и «Без звука» не умеет.

Коротко: настройка личная и живёт на сервере — `ConversationParticipant.mutedUntil`. Пуши (FCM/APNs) по
заглушённой беседе режет сам сервер — выгруженные телефоны и старые клиенты замолкают сразу. Звук, плашки и
локальные уведомления в открытом приложении глушит клиент: по `message:notify.muted` и по своему состоянию,
которое он держит по списку бесед, событию `conversation:mute` и снапшоту при подключении.

## 1. Значение

| `mutedUntil` (ISO, UTC, часы сервера) | Смысл |
|---|---|
| `null` | звук включён |
| момент в будущем | заглушено до этого момента |
| момент в прошлом | истекло — то же, что `null` (сервер сам отдаёт `null`, в БД ничего не стирает) |
| `"2100-01-01T00:00:00.000Z"` | «Навсегда» (`mutedForever: true`) |

Заглушено ⇔ `mutedUntil != null && mutedUntil > now` (строго). «Навсегда» ⇔ `mutedUntil ≥ 2099-12-31T00:00Z`
(или `mutedForever: true` от сервера). Выход из группы (удаление строки участия) сбрасывает «Без звука».

Чужой `mutedUntil` сервер не отдаёт никому: Prisma-клиент опускает поле глобально (`src/lib/prisma.ts`),
поэтому в `participants[]` (список бесед, `conversations:updated`, треды, бот) его нет. Видно только своё — в
полях ниже.

## 2. REST

### `POST /api/conversations/:id/mute`

Аутентификация обычная. Лимит — 30 запросов в минуту на человека (`429 {code:"RATE_LIMITED"}`).
Тело — **ровно одно** из:

| Тело | Что делает |
|---|---|
| `{"for": "1h" \| "8h" \| "1d" \| "1w" \| "forever"}` | срок от часов **сервера**: +1 ч, +8 ч, +24 ч, +7×24 ч, «Навсегда». **Клиентам — этот вариант**: неверные часы телефона не превратят «1 час» в «0 минут» |
| `{"until": "<ISO-8601 с поясом>"}` | точный срок (на будущее: «до утра»). `≤ now` → включить звук; дальше `now + 366 суток` → «Навсегда» |
| `{"until": null}` | «Включить звук» |

Посторонние поля (например `deviceId`) не мешают. `until` — только полный ISO с поясом: `2026-10-11T18:30:00Z`,
`2026-10-11T21:30:00.000+03:00`.

Ответ `200`:
```json
{ "conversationId": "cm…", "mutedUntil": "2026-10-11T18:30:00.000Z", "mutedForever": false, "serverNow": "2026-10-11T17:30:00.012Z" }
```
`mutedUntil` — то, что лежит в БД после записи (при гонке двух устройств — последнее записанное), `serverNow` —
момент изменения; он же `at` в событии `conversation:mute`.

Ошибки:
- `400 {code:"MUTE_BAD_BODY"}` — тело не подходит (нет ни `for`, ни `until`; оба сразу; неизвестный пресет;
  `until` не ISO);
- `404 {code:"NOT_A_PARTICIPANT"}` — не участник **или** беседы нет (одинаково — существование беседы не
  раскрывается);
- `429 {code:"RATE_LIMITED"}`.

Работает для любой беседы, где человек участник: группа, 1:1, «Чат с Еблушей», секретный тред любого статуса.
Повтор того же значения — `200` и событие ещё раз (безвредно). Устройство запроса (`did` токена /
`X-Device-Id`) уходит в событие как `byDeviceId`.

Старый сервер ответит `404` без `code` — клиент показывает «Не удалось изменить звук беседы».

### `GET /api/conversations` — новые поля

```json
{
  "conversations": [ { "conversation": { … }, "unreadCount": 3, "mutedUntil": "…" | null, "mutedForever": false, … } ],
  "serverNow": "2026-10-11T17:30:00.012Z",
  "totalUnread": 5
}
```
- в каждой строке — **свой** `mutedUntil` (уже нормализован: истёкший → `null`) и `mutedForever`;
- `serverNow` — момент **до** чтения списка: это `asOf` списка (см. §4);
- `totalUnread` — сумма `unreadCount` по **незаглушённым** беседам (общий счётчик, значок приложения).
  Тот же подсчёт, что у значка iOS (§5).

Старые клиенты новые поля игнорируют.

## 3. Сокет

| Событие | Кому | Тело |
|---|---|---|
| `conversation:mute` | `user:<я>` — все мои сокеты, включая поставивший | `{ conversationId, mutedUntil: ISO\|null, mutedForever: boolean, at: ISO, byDeviceId?: string }` |
| `conversation:mute:snapshot` | при **каждом** подключении сокета, только ему | `{ items: [{ conversationId, mutedUntil: ISO, mutedForever }], serverNow: ISO }` |
| `message:notify` | `user:<получатель>`, каждому отдельно | прежние поля + **`muted: boolean`** |

- `at` — момент изменения по часам сервера. Клиент применяет событие, только если `at ≥` своего `asOf` беседы.
- Снапшот — **замена целиком**: беседа, которой нет в `items`, НЕ заглушена (так долетает «Включить звук»,
  нажатый, пока устройство было без связи). Истёкших в нём нет.
- `message:notify.muted` — посчитано сервером для ЭТОГО получателя по правилу §6: `true` — не звенеть, не
  показывать уведомление/плашку; плитку, непрочитанное и порядок списка обновлять как обычно. Новый сервер
  шлёт поле всегда (`true`/`false`) — во всех `message:notify`: сообщения людей и бота, «начал звонок»,
  «Звонок продлился», «пригласил(а)», «покинул(а)». Нет поля — старый сервер: решать локальным правилом §6.
- В `message:new` (общая комната беседы) поля нет — оно у каждого своё.
- `secret:notify` не меняется: по нему клиент забирает секретное сообщение, глушить его нельзя.

## 4. Состояние на клиенте

На беседу хранится `{ mutedUntil, asOf }`. Источники и их `asOf`:

| Источник | `asOf` |
|---|---|
| `GET /api/conversations` | `serverNow` ответа (старый сервер — местное время отправки запроса) |
| `conversation:mute:snapshot` | `serverNow` (замена целиком: всем беседам не из `items` — `null` с этим `asOf`) |
| `conversation:mute` | `at` |
| ответ своего `POST …/mute` | `serverNow` |

Применять, только если новый `asOf ≥` сохранённого. Сервер гарантирует сходимость: `at` берётся после записи,
значение перечитывается после `at`, а `serverNow` списка/снапшота — до чтения.

Отображение — всегда `isMuted(mutedUntil, now)`, а не сохранённый флаг. Один таймер на ближайший неистёкший
не-«навсегда» срок (+50 мс) перерисовывает плитку и шапку; пересчёт — при возврате в приложение, пробуждении ПК
и переподключении. Где есть оценка смещения часов с сервером, сравнивать с поправленным now.

## 5. Пуши и значок

Сервер не ставит пуш `kind:"message"` получателю, которого правило §6 не будит:
- `src/lib/messageFanout.ts` — сообщения людей и бота (`POST /conversations/send`, `POST /api/bot/messages`);
- `src/routes/secret.ts` — секретные сообщения (`POST /secret/messages/push`); пробития нет;
- `src/realtime/socket.ts` — пуш «Групповой звонок»/«Групповой видеозвонок» при начале звонка в группе.

НЕ фильтруются: входящий 1:1 (`kind:"call"`, VoIP/CallKit), `call-cancel`, `kind:"read"`, «Пропущенный звонок»
1:1 (обычный и секретный). Звонок 1:1 «Без звука» не глушит.

Клиент пуши дополнительно не фильтрует — сервер уже решил (на Android можно страховочно проверить локальное
состояние на гонку «пуш поставлен за миг до заглушения»). Уже показанные уведомления при заглушении не
снимаются — их снимет read-sync.

У пушей о сообщениях (люди, бот, секретки, «Групповой звонок») есть `sentAt` — момент сообщения по часам
сервера: по нему страховка клиента отличает гонку от пуша, поставленного уже после заглушения.

**Значок iOS (`aps.badge`)** — `totalUnread` без заглушённых. Число ведёт **сервер** (`src/push/badge.ts`):
приложение, выгруженное свайпом, не получает ни сокета, ни тихих read-пушей, и посчитанное на телефоне число
залипало бы. Сервер ставит его:
- в каждый alert-пуш о сообщении;
- отдельным badge-only пушем (`apns-push-type: alert`, в `aps` только `badge`, кастомное поле `kind:"badge"`,
  `apns-collapse-id: badge`) — следом за read-пушем (прочитано на другом устройстве), сразу после смены
  «Без звука» и ещё раз в момент истечения срока. Его применяет сама система, приложение не будится.

Только устройствам, которые об этом попросили: iOS-сборка с поддержкой регистрирует alert-токен с
`caps: ["badge"]` (`POST /api/devices/:deviceId/push {token, provider:"apns", caps:["badge"]}`, при каждом
запуске) и получает в ответ `{ok:true, badge:true|false}`. `badge:true` — «число ведёт сервер»: только тогда
приложение вообще показывает значок (и само выставляет то же число по списку бесед, пока открыто), иначе держит
его пустым. Регистрация без `caps` (старая сборка, откат TestFlight) и снятие токена (`DELETE …/push`, выход)
объявление убирают. Хранится в Redis `push:badge:<userId>` (поле — `deviceId`, 180 суток с последней
регистрации). Старые сборки (≤ 995) значок не сбрасывают — им сервер числа не шлёт никогда.

`APNS_BADGE` — общий выключатель (по умолчанию `off`; тогда и `badge:false` в ответе). Включать можно в любой
момент: старые сборки не затрагиваются. Выключение: приложения узнают при следующем запуске и гасят значок.

## 6. Правило «будить ли» (одинаково на сервере и в клиентах)

`shouldAlert(беседа, сообщение, я, now)`:
1. своё сообщение → нет (как сейчас);
2. беседа не заглушена → да;
3. группа (`conversation.isGroup` — только серверный флаг, без эвристик по числу участников):
   - ответ на МОЁ сообщение (`message.replyTo.senderId == я`), в т.ч. ответ бота на мой вопрос → **да**;
   - упоминание меня → да: сейчас это только напоминание таймера обещания обещавшему (`metadata.bot.mentions`,
     сервер — `publishNewMessage({mentions})`, docs/bot-cards.md §2.3); @-упоминаний людьми пока нет;
   - всё остальное, включая «X начал звонок» и «Звонок продлился» → нет;
4. 1:1, «Чат с Еблушей», секретная: только записи о звонке — `type == "SYSTEM"` и
   (`metadata.missed` или `metadata.ended`) → **да**; остальное, включая ответ на моё → нет.

| Беседа | Сообщение | Будить |
|---|---|---|
| группа | ответ на моё (человек или бот) | да |
| группа | упоминание меня (напоминание таймера обещавшему; @ людей — будущее) | да |
| группа | остальное, включая «начал звонок» и «продлился» | нет |
| 1:1, «Чат с Еблушей», секретная | любое сообщение | нет |
| 1:1 | входящий, «Пропущенный звонок», «Звонок продлился» | да |

Ответ бота на обращение бывает несколькими сообщениями: `replyToId` есть только у первой части — она и пробивает,
остальные приходят молча. Секретное сообщение: будить, только если тред не заглушён (локальная плашка секретки о
пропущенном звонке 1:1 — по правилу звонка, показывать).

Групповой звонок в заглушённой группе — тихая отметка: плитка «В ЗВОНКЕ», кнопка входа, системная запись,
серое непрочитанное; ни пуша, ни звука, ни плашки «начал звонок».

**Тест-векторы** (`test/conversation-mute-rules.test.ts`; те же — в Vitest / JUnit / XCTest / самопроверке натива):
`null` → не заглушено; `now+1ms` → да; `now` → нет; FOREVER → да + «навсегда»; группа + ответ на моё → будить;
группа + ответ на чужое → нет; группа + «начал звонок» → нет; группа + ответ бота на моё → будить; 1:1 + ответ на
моё → нет; 1:1 + SYSTEM missed → будить; 1:1 + SYSTEM ended → будить; бот-чат + ответ бота на моё → нет;
секретка → нет.

## 7. Интерфейс (одинаково на всех платформах)

| Место | Текст |
|---|---|
| пункт меню, беседа не заглушена | «Без звука» (десктоп — подменю, телефон — лист) |
| заголовок листа выбора срока | «Без звука на…» |
| варианты | «1 час», «8 часов», «1 день», «1 неделю», «Навсегда» (на телефоне ещё «Отмена») |
| пункт меню, беседа заглушена | «Включить звук»; справа/второй строкой срок: «до 18:30», «навсегда» |
| подсказка значка | «Без звука до 18:30» / «…до завтра, 18:30» / «…до 14 окт., 18:30» / «…до 14 окт. 2027, 18:30» / «Без звука навсегда» |
| после действия | «Без звука на 1 час» / «…на 8 часов» / «…на 1 день» / «…на 1 неделю» / «Без звука навсегда» / «Звук включён» |
| ошибка | «Не удалось изменить звук беседы» |

Срок — местное время устройства: сегодня `до HH:mm`; завтра `до завтра, HH:mm`; в этом году `до d MMM, HH:mm`
(янв., февр., мар., апр., мая, июня, июля, авг., сент., окт., нояб., дек.); иначе `до d MMM yyyy, HH:mm`.

Заглушённая беседа: перечёркнутый колокольчик после названия на плитке и в шапке; «N непрочитанных»/капсула —
приглушённым цветом; рамка плитки от непрочитанного не загорается (от идущего звонка — загорается). Порядок
списка, «Отметить прочитанным», read-sync — без изменений. В общий счётчик заглушённые не входят.

## 8. Совместимость и выпуск

Контракт аддитивный, миграции нет (поле есть с init-миграции). Выпускать **сервер первым**: новые клиенты против
старого сервера получат `404` на `POST …/mute` и `message:notify` без `muted`.

Старые клиенты: пуши по заглушённым беседам пропадают сразу (это решает сервер), но их собственные сокетные
уведомления и звуки продолжатся до обновления (Android ≤ 0.3.41, натив ≤ 2.0.10, вкладка веба до перезагрузки,
звук iOS в открытом приложении). Electron заморожен — плашки и звук у него останутся.

Откат сервера: значения в БД останутся, а старый сервер снова начнёт отдавать `participants[].mutedUntil` другим
участникам (UI их нигде не показывает). Если это неприемлемо — после отката
`UPDATE "ConversationParticipant" SET "mutedUntil" = NULL` (стирает настройки людей — решение владельца).
