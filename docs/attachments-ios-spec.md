# Прикрепление фото и файлов — спека по iOS-клиенту (для паритета Android)

Состояние на 2026-10-11, iOS-сборка 914. Эталон всего ниже — код `ios/Eblusha/…`; при
расхождении прав код. iOS сам приведён к вебу (`frontend/src/ui/pages/chats/`), поэтому
везде, где написано «как веб», Android может сверяться и с вебом.

Файлы iOS, где это живёт:
- `Features/Chat/AttachmentSheet.swift` — лист прикрепления (сетка медиатеки, строки).
- `Features/Chat/ComposerAttachments.swift` — скрепка, системные пикеры, чтение файлов,
  лимит размера, очередь чипов над композером, накладка отправляемого пузыря.
- `Features/Chat/ChatComposer.swift` — камера, `openPicked` (картинки → редактор),
  вставка из буфера, отправка.
- `Features/Chat/ChatViewModel.swift` — `stageFiles`, `sendStaged`, `sendAttachments`,
  оптимистичный пузырь, повтор/отмена/удаление.
- `Core/Repository/ChatRepositoryUploads.swift` — загрузка на сервер и отправка сообщения.
- `Features/Chat/AttachmentAlbum.swift`, `Domain/ChatModels.swift` — мозаика альбома,
  размеры плиток, плитка видео.
- `Features/Chat/InlineVideoPlayer.swift` — автоплей коротких видео в ленте.
- `Features/Chat/AttachmentOpening.swift` — открытие видео и файлов.
- `Features/PhotoEditor/` — редактор фото перед отправкой.

---

## 1. Сквозной сценарий

1. Тап по скрепке → **лист прикрепления** (половина экрана, переписка видна сверху).
2. Человек выбирает кадры в сетке или идёт в «Фото или видео» / «Камера» / «Файл».
3. Выбранное читается в память. **Картинки открываются в редакторе**, всё прочее сразу
   встаёт **чипами** в очередь над полем ввода.
4. Подпись набирается в обычном поле ввода. Ничего не уходит, пока не нажата кнопка
   отправки композера (веб-паритет: случайный тап ничего не шлёт).
5. Отправка: очередь чистится сразу, в ленте сразу появляется **оптимистичный пузырь** с
   локальными превью, затемнением, кольцом прогресса и крестиком отмены. Поле ввода
   свободно: можно писать и слать дальше, пока это летит.
6. Файлы грузятся **по очереди**, затем уходит **одно** сообщение со всеми вложениями.
   Пузырь подменяется серверным сообщением. При сбое на пузыре появляется «Не
   отправилось» с кнопками «Повторить» и «Удалить».

## 2. Лист прикрепления

- **Сетка последних кадров медиатеки**: только фото и видео, от новых к старым, не больше
  **150**. Весь архив доступен через строку «Фото или видео». На видео — длительность
  `м:сс` / `ч:мм:сс`.
- **Выбор в порядке тапов с НОМЕРАМИ на кадрах** (1, 2, 3…), а не галочками: номер сразу
  говорит, что уйдёт и в каком порядке собеседник это увидит. Порядок тапов = порядок
  альбома. Снятие выбора из середины перенумеровывает хвост. Выбранный кадр слегка
  поджимается и обводится, номер появляется пружинкой.
- **Не больше 10 кадров за раз**. При попытке выбрать больше — подпись «Больше 10 кадров за
  раз не уйдёт».
- Кнопка **«Отправить N»** со счётчиком. Сама она ничего не отправляет: лист закрывается,
  выбранное идёт тем же путём, что и из системного пикера (картинки в редактор, прочее в
  чипы).
- Строки под сеткой: **«Фото или видео»** (системный пикер на весь архив, до 10, номера в
  порядке тапов), **«Камера»** (скрыта, если камеры нет), **«Файл»** (системный выбор
  документов, до 10).
- **Разрешение на медиатеку** спрашивается **один раз и только при открытии листа** (по
  явному намерению). Если доступ запрещён, на месте сетки текст «Доступ к медиатеке
  закрыт» + «Разрешите доступ к фото — и последние кадры будут прямо здесь. Без него
  выбрать снимок всё равно можно: «Фото или видео» ниже.» + кнопка «Открыть настройки».
  Строки под сеткой работают без всякого доступа.
- **Ограниченный доступ** («выбранные фото») — полноценный режим: сетка показывает
  разрешённое, отдельная строка «Выбрать ещё фото» вызывает системный выбор, после него
  сетка перечитывается.
- Пустая медиатека — «В медиатеке пока нет снимков». До первой загрузки — спиннер, а не
  «пусто».
- Миниатюры не тянут оригиналы из облака (только локальные превью). Кэш миниатюр
  гасится, когда лист закрыт.

Android: сетка — MediaStore (`READ_MEDIA_IMAGES/VIDEO`, на 14+ — частичный доступ
`READ_MEDIA_VISUAL_USER_SELECTED` как аналог «выбранных фото»), системный пикер — Photo
Picker (`PickMultipleVisualMedia(10)`), документы — `OpenMultipleDocuments`.

## 3. Чтение выбранного (что становится файлом)

Единица — `OutgoingFile { bytes, name, mime }`. Правило **«всё или ничего»**: если не
прочиталось хоть что-то из набора, ничего не встаёт в очередь, причина уходит в баннер
ошибок.

- **Фото из медиатеки** — байты **оригинала** (EXIF и качество целы), в версии **с
  правками** из «Фото». Если оригинал лежит только в облаке, его можно скачать.
- **HEIC/HEIF → JPEG, качество 0.9** на всех входах. HEIC не показывают ни веб, ни
  Android. Имя получает расширение под фактический формат (`IMG_0001.HEIC` →
  `IMG_0001.jpg`).
- **Видео** — тоже в версии с правками (обрезка и т. п.). Читается файлом на диск с
  отображением в память (mmap), а не целиком в RAM: иначе ролик в полгигабайта убивает
  процесс. mime: `video/quicktime` или `video/mp4`, прочее → `video/mp4`.
- **Документы** — копия к себе во временную папку (доступ к документу провайдера кончается,
  а отправка может идти минутами), чтение тоже через mmap. **Размер проверяется ДО
  чтения.**
- **Имена**:
  - из медиатеки — исходное имя файла;
  - из системного пикера, где имени нет, — `photo-yyyyMMdd-HHmmss-N.jpg` (N — порядковый
    номер выбора);
  - камера — `photo-<штамп>.jpg` / `video-<штамп>.mov`;
  - вставка из буфера — `photo-<штамп>.jpg` (несколько картинок — `photo-<штамп>-N.jpg`).
- **Камера**: фото → JPEG 0.9, сразу в редактор. Видео → `video/quicktime`, сразу в очередь.
  Отдельной отсечки по размеру у камеры нет: лимит один на все входы (см. §5).
- **Вставка из буфера** (картинка) — в очередь **мимо** редактора, как веб `onPaste`.
  Править можно тапом по чипу. Пустой буфер — «В буфере обмена нет картинки».
- Тексты ошибок: «Не удалось прочитать выбранные файлы», «Не удалось прочитать «<имя>»»,
  «Не удалось прочитать снимок», «Не удалось прочитать снятое видео».
- Пока набор читается (может занять секунды), скрепка гаснет.
- Временная папка подметается от остатков прошлых отправок (упавших, отменённых,
  прерванных перезапуском).

## 4. Редактор и очередь чипов

- **Картинки из листа, системного пикера и камеры сначала идут в редактор** (одной
  сессией все картинки набора). Остальные файлы набора проходят мимо и встают в очередь
  вместе с результатом редактора. Редактор — `Features/PhotoEditor/`: обрезка/поворот,
  коррекция, рисование, текст, стикеры, размытие. Экспорт в JPEG 0.9.
- **Очередь над полем ввода**:
  - картинка — миниатюра **64×64**, тап открывает её в редакторе (карандаш в нижнем левом
    углу);
  - прочий файл — иконка + имя, чип **96×64**;
  - крестик удаления — в верхнем правом углу;
  - **номер кадра в альбоме** — в верхнем левом углу, только у картинок и только если их
    ≥2. Номер = позиция среди картинок очереди, удаление из середины перенумеровывает.
- **Лимиты очереди: 10 картинок + 10 прочих.** Видео считается «прочим». Лишнее
  отрезается с ошибкой «Максимум 10 фото и 10 файлов за раз».
- Миниатюры чипов декодируются один раз в фоне и ужимаются (исходник бывает до 25 МБ).
- Подпись = текст в поле ввода. При отправке с очередью текст уходит **подписью** сообщения
  с вложениями, пустой текст — без подписи.

## 5. Отправка

Проверки до отправки (при отказе очередь не трогается, подпись возвращается в поле):
- живой черновик пересылки → «Сначала отправьте или отмените пересылку — вложения с ней не
  уходят»;
- **лимит размера = серверный: 1 ГБ на файл** (multer `limits.fileSize`, nginx
  `client_max_body_size 1024m`). Своего более жёсткого лимита у клиента нет. Текст:
  «Файл «<имя>» весит <N> — сервер принимает вложения до 1 ГБ»;
- капы 10+10 применяются **до** проверки размера, чтобы 11-й негабарит не отменил
  нормальный альбом.

Состав сообщения:
- **Все файлы очереди — одно сообщение.** Порядок вложений: сначала картинки (в порядке
  очереди, он задаёт мозаику), потом прочие.
- Тип сообщения по правилу веба: все вложения одного типа → этот тип (`IMAGE` / `VIDEO` /
  `AUDIO`), смесь → `FILE`. Тип вложения по mime: `image/*` → IMAGE, `video/*` → VIDEO,
  `audio/*` → AUDIO, прочее → FILE.
- Цитата уходит **вместе** с вложениями: `replyToId` = последняя цитата. При
  мультиответе (≥2 цитаты) все цитаты кладутся в `metadata`, одиночная — только
  `replyToId`. Плашка цитаты гасится сразу при отправке.
- Гейта «идёт предыдущая отправка» **нет**: каждая отправка живёт своим пузырём, их может
  лететь несколько.

**Оптимистичный пузырь**:
- временный id с префиксом; тот же тип сообщения, что получится на сервере, чтобы пузырь не
  перестраивался при подмене; локальные превью;
- накладка: затемнение, кольцо прогресса с процентами (общий прогресс по **байтам всех
  файлов** сообщения), крестик отмены. Затемнение глушит тапы: открыть просмотрщик или меню
  на неотправленном нельзя;
- **отмена** — пузырь исчезает сразу, загрузка бросается на ближайшей части, серверная
  сессия чанков удаляется;
- **сбой** — «Не отправилось» + «Повторить» (та же отправка теми же файлами в тот же пузырь)
  / «Удалить». Причина ошибки показывается на пузыре: баннер композера показывает только
  последнюю;
- **эхо**: если серверное сообщение пришло по сокету раньше ответа на отправку,
  оптимистичный пузырь снимается. Сопоставление по составу и только среди уже догруженных
  пузырей, по id нельзя.

**Секретные чаты** — отдельный путь: вложения шифруются ключом треда и уходят
непрозрачными блобами. Там пока старая механика: без оптимистичного пузыря, полоса
прогресса с отменой над композером, одна отправка за раз («Подождите — идёт отправка
предыдущего сообщения»), очередь чистится по факту успеха.

## 6. Протокол загрузки (сервер общий для всех клиентов)

Каждый файл грузится отдельно, **строго последовательно** (параллельные загрузки
упираются в rate-limit и путают порядок альбома). Падение любого файла отменяет отправку
целиком: частичного альбома не бывает.

**Простой путь** — `POST /api/upload`, multipart-поле `file` (filename + mime). Порог:
- **картинки ≤ 25 МБ** (только на этом пути сервер делает превью-thumb — без него каждый
  показ пузыря качал бы полный размер);
- **прочее ≤ 10 МБ**.

**Чанковый путь** (больше порога):
1. `POST /api/upload/init` `{ filename, contentType, size }` → `{ uploadId, chunkSize }`.
2. `PUT /api/upload/{uploadId}/part/{n}` — сырые байты, n с 0. Каждая часть ровно
   `chunkSize`, последняя — остаток (сервер сверяет).
3. Проверка отмены перед завершением, затем `POST /api/upload/{uploadId}/complete`.
4. При отмене или сбое — `DELETE /api/upload/{uploadId}` (уходит даже из уже отменённой
   задачи, иначе части висят на сервере).

Оба пути возвращают `{ url: "/api/files/{key}", path: <objectKey>, … }`.
Загрузки идут отдельной сессией с длинным таймаутом простоя. На 401 — одна тихая ротация
токена и один повтор.

**Сообщение** — `POST /api/conversations/send`:
```json
{
  "conversationId": "…",
  "type": "IMAGE | VIDEO | AUDIO | FILE",
  "content": "подпись или null",
  "replyToId": "…или null",
  "attachments": [{
    "url": "/api/files/{key}",
    "type": "IMAGE",
    "size": 123456,
    "metadata": {
      "originalName": "IMG_0001.jpg",
      "mime": "image/jpeg",
      "objectKey": "<path из ответа загрузки>",
      "width": 4032, "height": 3024
    }
  }],
  "metadata": { "…мультиответ / режим «Спросить», если есть" }
}
```
`width/height` — только у картинок, в пикселях. По ним **все** клиенты строят плитки
до загрузки картинок. Без них веб и iOS берут запасные пропорции, а лента прыгает.

## 7. Показ в ленте

**Альбом фото** (`AlbumLayout`, порт веб-`renderImageGroup`): каждая плитка держит **свою
пропорцию кадра**, ширины колонок подбираются так, чтобы высоты соседей совпали. Ни
серых полей, ни обрезки. Геометрия считается **из метаданных до загрузки**.
- Пропорция r = h/w, зажата в **[0.2, 5]**, мусор → 1.
- 1 фото — одиночная плитка; 2 — **рядом** (ширины обратно пропорциональны r, высоты
  равны), но **два широких кадра** (оба r < 0.9) — **столбиком**; 3 — большая слева + две
  стопкой справа; 4+ — сетка 2×2 (слева 0 и 2, справа 1 и 3), сверх 4 — **«+N»** на
  последней видимой плитке.
- Зазор **4 pt**, скругление у всего блока, минимальная ширина мозаики **220**.
- Бюджет: ширина `min(max(280, 0.85·экран), экран − 120 − отступы)`, высота
  `min(420, 0.55·высоты экрана)`. Ширина уменьшается, если по высоте не влезает.
- Коэффициент высоты блока (H/W): 1 → r0; ряд из двух → r0·r1/(r0+r1); столбик → r0+r1;
  3 → r0·(r1+r2)/(r0+r1+r2); 2×2 → (r0+r2)(r1+r3)/(r0+r1+r2+r3).
  Зазоры учитываются при раскладке в пикселях, чтобы колонки кончались на одной линии.
- **Одиночная картинка**: `maxScreen = max(320, ширина/2)`, бюджет высоты
  `min(420, 0.55·высоты)`; для широких кадров потолок высоты ниже (r < 0.5 →
  `max(0.6·maxScreen, 200)`, r < 0.7 → `max(0.75·maxScreen, 200)`). Без метаданных — 4:3.
- Картинка рисуется в плитке через `fill`: пропорция плитки уже равна пропорции кадра.

**Видео**: плитка с серверным постером (`metadata.posterKey`), круглой кнопкой Play и
угловой подписью «1:23 · 12 МБ». Размер — как у картинки, без метаданных **16:9**.
Автоплей в ленте:
- без звука, циклом, только пока плитка на экране;
- только ролики **≤ 30 с и ≤ 8 МБ**, не больше **2 одновременно**;
- старт при видимости ≥ 70 % после остановки прокрутки, стоп при < 35 %;
- кроссфейд постер ↔ видео 0,18 с;
- настройка «Никогда / Только Wi-Fi / Всегда»;
- в секретках автоплея и постера нет (сервер видит только шифртекст).

Тап открывает полноэкранный плеер со звуком.

**Файл** — строка: иконка, имя, размер. При открытии файл скачивается с процентом и
отменой крестиком прямо на строке.

**Открытие**:
- фото → просмотрщик (галерея всех фото беседы, кадр вырастает из плитки и улетает назад в
  неё);
- видео → полноэкранный плеер;
- документ → системный предпросмотр с «Поделиться» (на Android — `ACTION_VIEW` через
  FileProvider).

Прокси `/api/files` требует Bearer, поэтому файл сначала скачивается во временный файл с
человеческим именем. Секретное вложение перед показом расшифровывается в кэш-файл.

## 8. Чек-лист паритета для Android

- [ ] Свой лист с сеткой последних 150 кадров, выбор с номерами, лимит 10, «Отправить N».
- [ ] Строки «Фото или видео» (системный пикер, порядок тапов), «Камера», «Файл».
- [ ] Разрешение только при открытии листа; экран отказа; частичный доступ + «Выбрать ещё».
- [ ] HEIC → JPEG 0.9, оригинальные байты фото, видео и документы без загрузки в RAM.
- [ ] Картинки → редактор, прочее → чипы; вставка из буфера мимо редактора.
- [ ] Чипы 64×64 / 96×64, номера альбома, тап по картинке — в редактор; лимит 10+10.
- [ ] Подпись из поля ввода, одно сообщение на всю очередь, тип по правилу «все одного вида».
- [ ] Лимит 1 ГБ с понятным текстом; проверка до чтения.
- [ ] Оптимистичный пузырь: прогресс по байтам, отмена, «Не отправилось» + повтор/удалить,
      снятие эха.
- [ ] Загрузка последовательная; multipart до 25 МБ (картинки) / 10 МБ (прочее), дальше чанки
      с abort.
- [ ] `metadata.width/height` у картинок, `originalName`, `mime`, `objectKey`.
- [ ] Мозаика альбома по формулам §7, плитки по метаданным до загрузки.
- [ ] Видео-плитка с постером и автоплеем по правилам §7.
- [ ] Открытие: просмотрщик / плеер / системный просмотр файла.
