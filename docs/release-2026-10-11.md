# Единый выпуск 2026-10-11: сервер, бот, веб, ПК 2.0.11, Android 0.3.42, iPhone

Решение владельца: всё клиентское — одним выпуском. Внутри: «Без звука» для бесед, карточки бота (таймер обещания,
«поделиться перепиской», «Подумай лучше»), справочник бота по приложению, летопись Valheim (`valheim_history`),
окно ПК не свёрнутым и поверх, iOS LinkNeeded. Контракты — `docs/conversation-mute.md`, `docs/bot-cards.md`.

| Что | Откуда |
|---|---|
| сервер, бот, веб, iOS | ветка `release/2026-10-11` (worktree `/DATA/eb-release-wt`), от `e6438fbe` |
| ПК 2.0.11 | `scratchpad/winui-git`, ветка `rel-2.0.11` (`b31438f`) (worktree `scratchpad/winui-wt/rel-2.0.11`), зеркало `D:/claude-backup/winui-git.git` |
| Android 0.3.42 | живое дерево `C:/projects/eblusha-mobile` (не под git): 0.3.41 + «Без звука» + карточки |

Порядок: **точки отката → сервер → бот → веб → ПК → Android → iPhone → номера версий в справочнике**. Сервер всегда
первым: новые клиенты против старого сервера получат 404 на `…/mute` и карточки без живого вида. Перезапуск backend
рвёт звонки — по приказу владельца не ждём тихого окна.

## 0. Точки отката (до любых изменений)

```bash
cd /DATA/eblusha-plus
```

## 1. Сервер (backend + worker)

```bash
cd /DATA/eblusha-plus
git merge --ff-only release/2026-10-11   # чужие незакоммиченные Dockerfile, nginx-…inc, get/index.html не пересекаются и остаются
grep -q '^APNS_BADGE=' .env || echo 'APNS_BADGE=on' >> .env
docker compose -f deploy/docker-compose.full.yml --env-file .env build backend worker
docker compose -f deploy/docker-compose.full.yml --env-file .env up -d --no-deps --no-build backend worker
docker logs --since 3m eblusha-backend 2>&1 | grep -iE 'migrat|error' | tail
```

- Образ собирается с правленым Dockerfile рабочего дерева — так всегда, не «чинить».
- Миграция `20261011150000_bot_cards` применяется при старте (`prisma migrate deploy`): только `CREATE TYPE/TABLE/INDEX`
  и внешние ключи на пустых таблицах `PromiseTimer`, `BotShare`. Мьюту миграция не нужна (`mutedUntil` есть с init).
- `APNS_BADGE=on` — сразу, в этом же перезапуске: число на значке получают только устройства, приславшие caps `badge`
  (новая iOS-сборка), старым ничего не уходит. Включать позже = второй перезапуск backend и worker (снова рвёт звонки).
- Выключатели без отката: `PROMISE_TIMERS=off`, `BOT_SHARE=off` в `.env` + `up -d --no-deps --no-build backend worker`.

## 2. Бот

```bash

docker logs --since 2m eblusha-bot 2>&1 | grep -E 'knowledge\.loaded|valheim\.start|boot'
```

- ⚠️ Только с `--no-deps` и именем сервиса: `--profile bot up -d --force-recreate` без них пересоздаст ВСЕ сервисы,
  включая postgres, redis и livekit.
- Ждать в журнале: `knowledge.loaded` (`checked: 2026-10-11`, ~15 тыс. токенов) и `valheim.start` с полем `history`.
  Каталог `/DATA/valheim-history/export` монтируется только на чтение; без него compose бота не поднимет.
- Справочник вшит в образ. В нём пока Android 0.3.41 и iPhone 995 — это правда, пока новые не опубликованы; номера
  меняет шаг 7.
- `.env.bot`: умолчания есть для всего. «Подумай лучше» — `BOT_DEEP*` (claude-fable-5-1, запасная claude-opus-5-5; 5 в

сотрёт `build/archive`, не собрав новый). Справочник на шаге 7 — «сборка 1034».

**Сборка С расширением — 1036 (2026-10-11 09:19–09:27Z, `5f6e2aab`).** Владелец завёл App Group `group.org.eblusha.plus`,
App ID `org.eblusha.plus.NotificationService` (App Groups) и App Groups у `org.eblusha.plus`. Пока у `org.eblusha.plus` способности
APP_GROUPS не было (её видно ASC-ключом: `GET /v1/bundleIds?filter[identifier]=org.eblusha.plus&include=bundleIdCapabilities`;

это Xcode пытался ключом сам включить способность у App ID и не мог, сам ключ исправен. Дальше автоподпись всё сделала сама
(профили разработки и Store для обоих таргетов): `EBLUSHA_BUILD_NUMBER=1036 scripts/ios-release.sh --no-upload` → проверка → `--upload-only`,
«Upload succeeded» 09:25:19Z, VALID / IN_BETA_TESTING. В .ipa: `PlugIns/EblushaNotificationService.appex` (1.0/1036,
`com.apple.usernotifications.service`), у приложения и расширения `com.apple.security.application-groups = [group.org.eblusha.plus]`,
aps-environment production (в архиве development), `keychain-access-groups` нет ни в архиве, ни в .ipa — как у 1034, ключи E2EE на
телефонах на месте; единственное отличие entitlements приложения от 1034 — группа приложений. Подпись Apple Distribution 4748P9MT6D,
`codesign --verify --deep --strict` ok. Архив 1034 и его entitlements для сравнения — на маке `~/builds/eblusha-ios-1034-base/`.

```bash
cd /DATA/eblusha-plus
N=$(git rev-list --count HEAD); echo "сборка $N"        # закрепить номер ДО коммита справочника (шаг 7)
EBLUSHA_BUILD_NUMBER=$N scripts/ios-release.sh --no-upload   # архив + подпись; App ID расширения и App Group заводит автоподпись
EBLUSHA_BUILD_NUMBER=$N scripts/ios-release.sh --upload-only
```

- Скрипт сам будит мак (Wake-on-LAN раз в 5 с на всё время работы, удалённая часть — под caffeinate) и не начинает,
  если мак на батарее и заряд ниже 15 % (`EBLUSHA_IOS_MIN_BATTERY`): сядет посреди archive — после включения
  FileVault ждёт пароля человека. 2026-10-11 ~04:30Z мак был на батарее, 18 % и разряжался.
- **Запасной путь, если подпись упала** на профиле, App ID `org.eblusha.plus.NotificationService` или группе
  `group.org.eblusha.plus`: `EBLUSHA_BUILD_NUMBER=$N scripts/ios-release.sh --without-nse --no-upload`, затем
  `--upload-only`. Правится копия `ios/` (без таргета расширения и без группы приложений), репозиторий и номер не
  меняются. Без расширения теряется только приглушение пуша, пришедшего в гонке с «Без звука»; число на значке ведёт
  сервер (`APNS_BADGE`), настройки «Без звука» — `UserDefaults.standard`. Расширение — следующей сборкой, когда
  идентификаторы заведены.
- Мак не проснулся или заряда мало — iPhone выходит позже, остальное от этого не зависит. Решение «ждать ли iPhone»
  — за координатором; справочник тогда остаётся с 995 до выхода сборки.
