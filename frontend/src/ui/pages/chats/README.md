# `chats/` — модули страницы чатов

Экран мессенджера — это компонент [`../ChatsPage.tsx`](../ChatsPage.tsx). Он большой,
поэтому вся **чистая логика** (не зависящая от состояния компонента) и переиспользуемые
под-компоненты/хуки вынесены сюда, в `chats/`. Цель — чтобы `ChatsPage.tsx` держал в
себе только состояние экрана и его сборку, а «как посчитать/отрисовать конкретную
штуку» жило рядом маленькими файлами.

## Карта модулей

### Чистые данные и хелперы (без состояния, без React)

| Файл | Что внутри |
|------|-----------|
| `chatsConstants.ts` | Общие константы: ключ localStorage последней беседы, лимиты вложений, размер страницы истории и т.п. |
| `chatsColors.ts` | Палитры цвета имени автора (`NAME_COLOR_PALETTE_13/26`) и фонов пузырей (`BUBBLE_BG_BASES`). Цвет назначается по **позиции участника в беседе** (см. `participantColorIndex` в `ChatsPage`), а не по хешу — иначе разные люди в маленькой группе получали один цвет. |
| `chatsTime.ts` | Форматирование времени/дат сообщений в едином русском стиле (24ч, `ru-RU`): часы, «сегодня/вчера/N дней назад», подпись для маленьких карточек ответа/пересылки. |
| `chatsAttachments.ts` | Вложения и файлы: определение типа контента (изображение/видео/аудио/файл), человекочитаемые размер и скорость загрузки, имя файла из URL/`Content-Disposition`, иконка и подпись файловой плитки, типы «ожидающих» (оптимистичных) вложений/сообщений. |
| `chatsMessages.ts` | «Модель сообщения»: разбор `metadata`, тексты для копирования и системных сообщений, черновики ответов (**reply**) и вся логика пересылки (**forward**) — детект, отпечатки, сборка мульти-исходных пачек, заголовки и payload на отправку. Секционирован комментариями. |
| `chatsEmbeds.ts` | Открытие ссылок во внешнем/системном браузере и связанное с встраиванием. |
| `fluentReactionAssets.ts` | Карта эмодзи-реакций на цветные Fluent-PNG. |

### Виртуализация и рендер

| Файл | Что внутри |
|------|-----------|
| `chatsEblo.tsx` | «Eblo» — лёгкая ручная виртуализация списка сообщений: константы окна, типы, компонент `EbloMeasuredRow` (измеряет реальную высоту строки через `ResizeObserver`, чтобы держать в DOM только видимые строки и точно прилипать к низу). Логика выбора видимого окна и прилипания живёт в `ChatsPage` (регион `MESSAGE LIST VIEWPORT`), т.к. завязана на состояние. |
| `chatsTextRender.tsx` | Рендер текста сообщения: ссылки, переносы, markdown-путь. |

## Внутренняя структура `ChatsPage.tsx`

Файл всё ещё большой (в нём живёт состояние экрана и весь рендер). Чтобы по нему было
удобно перемещаться, крупные регионы помечены **баннерами-комментариями**
(`// ===== РЕГИОН: … =====`). Порядок сверху вниз:

1. Состояние, рефы, запросы данных, производные значения.
2. **SECRET CHAT** — старт/отправка секретных чатов, очередь ключей.
3. **OLDER MESSAGES** — подгрузка истории вверх (инфинити-скролл) со стабильной прокруткой.
4. **MESSAGE LIST VIEWPORT** — виртуализация Eblo + прилипание к низу (`pinToBottomBurst`,
   `ResizeObserver` контента) — держит последнее сообщение видимым при догрузке картинок.
5. Отправка/реакции/выделение/звонки и прочая логика.
6. `renderConversationList(mobile)` — сайдбар со списком бесед.
7. `renderMessagesPane(mobile)` — открытая беседа (шапка/сообщения/композер).
8. `renderActiveCallOverlay()` — оверлей активного звонка.
9. `return (...)` — сборка экрана.

## Дальнейшая декомпозиция

Следующие безопасные шаги (делать **пошагово**, с тайпчеком/сборкой на каждом):

- Вынести регион **MESSAGE LIST VIEWPORT** в хук `useMessageListViewport` — самый связный
  подсистемный кусок. Осторожно: логика прокрутки/виртуализации переплетена с
  `loadOlderMessages` и композером, поэтому нужен аккуратный интерфейс и проверка
  прокрутки на живом приложении после выноса.
- Вынести под-компоненты рендера (входящий/исходящий диалоги звонка, модалки
  создания беседы/добавления участников) — через явные пропсы.
