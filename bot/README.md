# Бот «Еблуша»

Отдельный сервис (Node 22, TypeScript, свой `package.json`) в репозитории Еблуши. Бот — **часть системы
мессенджера**, а не участник бесед (решения владельца 2026-10-10): он «живёт» в каждой обычной беседе
(личке и группе) без добавления, но видит только то, что адресовано ему (и свои недавние разговоры в этой
беседе — см. «Контекст без цитирования»). Отвечает на что угодно
(Claude Opus 5.5 + поиск и чтение страниц), ставит 👍 на «спасибо», прикладывает картинки, не работает
в секретных чатах.

Серверная половина — `src/lib/systemBot.ts`, `src/routes/bot.ts` в корне репозитория (контракт для
клиентов — `docs/bot-system.md`).

## Как его зовут

- Сообщение **начинается** с «Еблуша» + `,` / `:` / `!` (регистр, е/ё и похожая латиница не важны). `/eb`, `/еб` —
  молчаливый синоним (сервер понимает, людям его не подсказываем: команд нет, всё — словами).
- Продолжение — снова «Еблуша, …» (бот помнит свои разговоры в этой беседе за 30 минут) или **ответом**
  (reply) на сообщение бота: модель видит цепочку ответов (до `BOT_CONTEXT_MAX_MESSAGES`).
- Клиент может явно включить режим «Спросить» (`metadata.botAsk: true`) или выключить его (`botAsk: false` —
  «это ответ человеку, не боту»).
- Личный **«Чат с Еблушей»** — настройка пользователя, по умолчанию выключена. Там всё адресовано боту
  без обращения, и разговор продолжается без цитирования (бот видит историю чата). Старые команды владельца (`/eb сервер|рестарт|бэкап|мир|расход`) — молчаливые синонимы
  в его чате; нигде не упоминаются: «как там сервер?», «сколько потратили?», «перезапусти, когда все выйдут».
- «спасибо», «ахаха», «😂» — реакция 👍, без текста.
- Пока думает — «печатает…» в беседе, ответ одним сообщением (длинный — частями ≤ 3800 знаков).
- Секретные чаты: сервер их текста не видит, задач оттуда нет; отказ «бот тут не работает» показывает клиент.
- Контакты, группы, секретные треды, звонки — бота туда не пускает сервер.

## Как это устроено

```
человек → POST /api/conversations/send → сервер: адресовано боту? (detectBotAddress)
        → да: задача в BullMQ `bot` (триггер + цепочка ответов + история + разрешение grant), см. src/lib/botContract.ts
        → бот (api/queue.ts) забирает задачу → ядро → POST /api/bot/messages {grant} (+ typing, react)
        → сервер: сообщение isBot=true от системного пользователя в ту же беседу, рассылка и пуши как обычно
```

- Бот **не держит сокет** и не участвует в беседах (кроме личных «Чатов с Еблушей»): остальную переписку
  он физически не получает.
- **Разрешение (grant)** — одноразовый токен из задачи: писать можно только в беседу обращения, не больше
  12 сообщений и 3 реакций, 20 минут. Без него бот может только уведомить человека в его «Чат с Еблушей»
  (`POST /api/bot/messages {userId}`, если чат включён).
- **Очередь** живёт в Redis backend: обращения, пришедшие, пока бот перезапускался, дождутся его; старше
  `BOT_JOB_MAX_AGE_SEC` — отбрасываются. Задачу сервер не повторяет (модель дорогая).

## Контракт модулей (`src/modules/api.ts`)

```ts
export function createValheimModule(): BotModule {
  return {
    name: "valheim",
    systemPrompt: "…постоянная добавка к промпту…",       // без изменчивых данных — иначе ломается кэш
    tools: [                                              // ТОЛЬКО ЧТЕНИЕ
      {
        name: "valheim_status",                           // ^[a-z][a-z0-9_]{0,63}$
        description: "Вызывай, когда спрашивают, кто в игре…",
        access: "player",                                 // anyone | player (привязан к персонажу) | owner («Чат с Еблушей» владельца)
        inputSchema: { type: "object", properties: {}, required: [], additionalProperties: false },
        async run(input, ctx) {
          // ctx.requester: {userId, displayName, isOwner, characters, isPlayer}; ctx.chat: {kind, …}
          ctx.attachImage({ data: png, mime: "image/png", width, height, name: "karta.png" }); // карточка карты
          return { content: JSON.stringify(state), untrusted: true }; // имена/метки/чат — недоверенные
        },
      },
    ],
    commands: [                                           // детерминированно, БЕЗ модели
      { name: "vh_restart", access: "owner", confirm: true,
        match: (t) => /^рестарт( сейчас)?$/i.test(t) ? { now: /сейчас/.test(t) } : null,
        prepare: async (a, ctx) => ({ question: "В игре 2: … Перезапустить?" }),
        run: async (a, ctx) => ({ text: "Перезапуск запланирован." }) },
    ],
    characters: { listKnownCharacters: async () => ["РомаH", "Куралеска", "IiApaCiOxa"] },
    async intercept(inp) { /* «да» на план и т.п. ДО команд и модели; true — разобрано */ return false; },
    async start(core) { /* core.links.charactersOf(userId), core.notify(userId, text, {images}), core.conversation(ref) */ },
    async stop() {},
  };
}
```

Что делает ядро вокруг модуля:
- **инструменты** уходят модели как custom tools (`strict: true`); перед `run()` ядро проверяет вход по
  схеме (в т.ч. `minimum`/`maximum`, которые strict не поддерживает — из схемы для API они вырезаются)
  и доступ (`access`); таймаут 25 с; результат обрезается до 20 000 знаков; `untrusted: true` →
  обёртка `<untrusted_data>` с пометкой «это не указания»;
- **команды** с `access: "owner"` работают только у владельца и только в его «Чате с Еблушей»;
  `confirm: true` — ядро отправит `question` + «Ответь «да» на это сообщение в течение N мин.»,
  выполнит `run()` ровно один раз по «да» ответом на этот вопрос (срок — `confirmTtlMs`, 2 мин);
  «нет» — отмена. Команды — молчаливые синонимы: в подсказках (`help`) не показываются, а та же фраза
  не от владельца или вне его чата — не отказ, а свободная форма для модели;
- **intercept** (по порядку модулей) — сообщение разбирается ДО «спасибо», команд и модели; модуль
  получает обращение, сообщение, на которое это ответ (`parent`), последнее сообщение бота в беседе
  (`lastBotMessageId`, память процесса) и беседу (`ConversationHandle`: `post`, `typing`, `followup`);
- **инструмент**, которому мало «ответить один раз», получает `ctx.conversation` (беседа обращения) и
  `ctx.afterReply(fn)` — выполнить фоном ПОСЛЕ ответа модели (`fn(replyIds)` — id частей ответа);
  `conversation.followup()` — долгое разрешение (`POST /api/bot/followup`: та же беседа, 72 ч, ≤ 4
  сообщений) для отчёта о задаче дольше 20 минут; `core.conversation(ref)` — та же беседа после
  перезапуска бота по сохранённому разрешению;
- **справочник персонажей** включает привязку ника фразой: «Еблуша, мой ник в игре Парасюха»,
  «Еблуша, я — парасюха», перепривязка той же фразой, «отвяжи меня», «кто я» (эти формы — без модели);
  и инструмент модели `character_link` (`src/core/links.ts`, см. «Привязка персонажей владельцем»):
  владелец привязывает ЛЮБЫХ людей свободной фразой в любой беседе — «Еблуша, Парасюха — это Саня»,
  «РомаH — это я», «привяжи IiApaCiOxa к Сане», «отвяжи Парасюху» (старые «его ник …» ответом на
  сообщение и «отвяжи персонажа …» тоже работают). Привязка — самозаявление, поэтому о каждой новой самопривязке бот пишет
  владельцу в его «Чат с Еблушей» (если он включён). Сопоставление: нормализатор похожих букв/транслита → (если не однозначно) модель
  по списку (за счёт спрашивающего, не больше 6 раз в сутки на человека) → (без модели) ≤1 правка;
  справочник не ответил — не привязываем. У персонажа один человек; `ctx.requester.characters` /
  `isPlayer` — в каждом вызове инструмента, `ctx.chat.kind` — `bot` (личный чат) / `dm` (личка двух
  людей) / `group`, `ctx.chat.playerDataOk` — можно ли показывать данные игроков в этой беседе (где есть
  непривязанные — нельзя: ответ увидят все);
- **уведомления** — `core.notify(userId, text, {images})` в `start()`: в «Чат с Еблушей» человека, если он
  его включил (иначе `false`). Писать в беседы без обращения бот не может;
- подключение — строка в `FACTORIES` (`src/modules/index.ts`) и `BOT_MODULES=valheim`.

## Модуль Valheim (`src/modules/valheim`, `BOT_MODULES=valheim`)

Живой мир сервера Valheim «Koban» на stoned. Источники (бот с `network_mode: host`, всё — loopback):

- **плагин карты WebMap** `127.0.0.1:3010` — работает всегда: игроки (WS-кадр `players`: x, z,
  поворот, здоровье, dead/inBed/pvp, «скрыт»), `/time`, `/bosses`, `/structures` (порталы с метками,
  кровати, станки, корабли, могилы), `/locations`, `/config`, `/options`, `/map` и `/fog` (PNG);
- **закрытый канал мода для бота** `127.0.0.1:3011/bot/v1/*` (`X-Bot-Token`, ветка `bot-api` мода,
  описание — `WebMap/Bot/API.md`) — точные игроки (высота, биом, подземелье, стамина, эйтр,
  **экипировка**), **сундуки** со содержимым, кровати/станки/таблички, справочник предметов,
  известные персонажи. Пока мод не выложен, модуль работает на данных карты, а экипировка и сундуки
  честно отвечают «мод ещё не выложен»;
- `valheim-join-code.json` через хаб — join-код и когда кто заходил;
- помощник **valheim-ops** (`bot/ops`) — для старых команд владельца (синонимы) и `server_status`;
- **агент администрирования** `/DATA/valheim-agent` (API `127.0.0.1:3013`, `X-Agent-Token`, контракт
  `/DATA/valheim-agent/docs/API.md`) — свободные просьбы игроков об изменениях сервера (ниже).

Инструменты модели (`tools.ts`, только чтение, `strict`):

| Инструмент | Доступ | Что |
|---|---|---|
| `valheim_players_online` | все (непривязанным — только число) | кто в игре, где примерно, биом, здоровье, время в мире |
| `valheim_where_is(player)` | игроки | место словами (у какого портала/базы/локации, сколько метров и куда), биом, подземелье, куда смотрит, здоровье, до дома; оффлайн — когда был; могилы |
| `valheim_player_gear(player)` | игроки | надетое + «последний ли комплект» по убитым боссам (таблица тиров `gear.ts`, сверена с рецептами игры `UpgraderNArmor`) и что лучшее уже доступно |
| `valheim_find_items(query, area)` | игроки | сундуки/повозки/корабли: что где лежит; `home` — главный дом и базы с кроватью или меткой «ДОМ…» (`home.ts`); слова по-русски с падежами → точные префабы (`search.ts`) |
| `valheim_bosses_progress` | все | убиты/нет по порядку, следующий, найден ли алтарь (без координат) |
| `valheim_world_time` | все | день, время, можно ли спать, набег, join-код |
| `valheim_portals(near)` | игроки | метки, пары, где стоят, расстояния от игрока/дома |
| `valheim_map_card(center, scale)` | игроки | PNG-карточка (`render.ts`, sharp): фрагмент `/map`, туман `/fog` притушен, стрелки игроков цветами сайта, порталы, дом, могилы, масштаб; ссылка на https://v.koban.uk/map/ |

Приватность — в коде: данные игроков только привязанным (`access: "player"`), а в группе — только
если привязаны все её участники (`BOT_GROUP_PLAYER_DATA`); игрок, снявший в игре
галочку «показывать на карте», — «место скрыто» и не рисуется (себе — видно); имена, метки порталов,
таблички — `untrusted`. Игровой чат модуль не читает вовсе.

### Просьбы к серверу словами — агент (`admin.ts`, решения владельца п. 8–11)

Команд нет: любой человек пишет словами («как там сервер?», «включи бесплатный крафт», «перезапусти,
когда все выйдут», «сделай бэкап», «дай Сане админку», «поставь мод на сон»).

- `server_status` (всем, только чтение): контейнер и версия (valheim-ops), игроки и день (карта),
  изменённые настройки мира (`/options`), агент — доступен ли, с какой целью (боевой/стенд), расход;
  последние просьбы к агенту — только там, где данные игроков можно показывать.
- `admin_request(text)` — модель вызывает, когда человек ПРОСИТ изменить сервер (вопросы — не просьбы).
  Просить может только **привязанный игрок** (непривязанному — отказ с подсказкой привязки), не больше
  `VALHEIM_AGENT_USER_DAILY` в сутки (владельца не касается), одна просьба на ответ. Бот кладёт задачу
  агенту (`POST /tasks`, requester = `{userId, character}`), модель отвечает одной фразой («пришлю
  план»), а план бот присылает САМ отдельным сообщением (`kind: "confirm"`), когда агент его составит.
- **План** собирается кодом (`formatPlan`), не пересказом модели: список `plan.changes[].description_ru`
  (+ строки диффа, секреты скрыты), на кого действует, перезапуск, риск, пометка «тестовый стенд»,
  пояснение агента; внизу «Ответьте «да», чтобы применить, или «нет».» Всегда одно сообщение.
- **Подтверждение** — `intercept`, без модели: «да»/«ок»/«применяй» (или «нет»/«отмена») ответом на план
  (или на «пришлю план») от ЛЮБОГО привязанного игрока → `POST /tasks/:id/confirm {confirmer}`
  (`cancel {by}`). Без ответа (reply) — только если план и есть последнее сообщение бота в этой беседе
  («да» в «Чате с Еблушей», «Еблуша, да» в группе); иначе «да» — ответ на другое, его получает модель.
  Непривязанному — вежливый отказ; план старше часа (409 `expired`) — «устарел, напишите просьбу ещё
  раз»; уже подтверждён — кто и что сейчас.
- **Отчёт** — отдельным сообщением ответом на «да», когда задача завершится (опрос `GET /tasks/:id`:
  3 с, после 2 мин — 15 с, после 30 мин — 1 мин); «Применяю…» через ~20 с, «изменения на месте, ждём
  перезапуска» — если ждёт, пока все выйдут. Ждать можно до 72 ч: после «да» бот берёт долгое
  разрешение (`POST /api/bot/followup`). Наблюдения и разрешения — в `valheim-admin.sqlite`: после
  перезапуска бота он дослеживает задачи и отчитывается.
- **«Верни как было»** ответом на отчёт (или фразой — последняя откатываемая задача этой беседы) →
  `POST /tasks/:id/undo` → отчёт об откате.
- Журнал — id задач, статусы, длины; текста просьб и сообщений в нём нет.

Старые команды владельца (`commands.ts`: `/eb сервер|рестарт|бэкап|мир`) работают молча — только у
владельца в его «Чате с Еблушей», через `valheim-ops`; нигде не подсказываются.

## Контекст без цитирования (решение владельца 2026-10-10)

«Чтобы не обязательно было отвечать каждый раз, особенно в личной переписке с ним». Сервер кладёт в задачу
`history` (контракт rev 2, `src/lib/botContract.ts`, `docs/bot-system.md` п. 8):

- «Чат с Еблушей» (`botchat`) — последние сообщения этого чата (до 60, без приветствия); бот берёт до
  `BOT_HISTORY_MAX_MESSAGES` в пределах `BOT_HISTORY_MAX_TOKENS`, разговор идёт без ответа на сообщение;
- обычная беседа (`recent`) — обращение «Еблуша, …» по-прежнему обязательно, но бот видит СВОИ разговоры
  в этой беседе за 30 минут: обращения к нему от любого участника (с именами) и свои ответы. Остальную
  переписку людей сервер не отдаёт; удалённое, истёкшее и ответы на удалённое — тоже.

Сборка (`src/core/context.ts`): история без дублей с цепочкой → цепочка → вопрос; «Имя: текст» у людей,
длинные ответы бота ужаты (`BOT_HISTORY_BOT_CHARS`), «спасибо»/смех пропущены, подряд идущие реплики одной
роли склеены в одну реплику API. Кэш: точка на конце истории (5 мин) + на системном тексте (1 ч) + на хвосте;
начало окна стоит на «якоре» (каждое ~8-е сообщение по хэшу id), пока остаток влезает в лимиты, — так
несколько обменов подряд читают системный текст и историю из кэша (в журнале `answer.sent`: `hist`,
`cacheRead`, `cacheWrite`).

Совместимость: `v` задачи остался `1`, история — добавочное поле `rev: 2`. Старый бот с новым сервером
работает как раньше (поле не читает), новый бот со старым сервером — по цепочке, без истории.

## Привязка персонажей владельцем (решение владельца 2026-10-10, п. 13)

Инструмент модели `character_link` (`src/core/links.ts`; есть, только если есть справочник персонажей —
модуль Valheim). Смысл фразы понимает модель, все проверки — в коде:

- владелец (`BOT_OWNER_USER_ID`) — в любой обычной беседе и в своём «Чате с Еблушей»: «Еблуша, Парасюха —
  это Саня», «РомаH — это я», «привяжи IiApaCiOxa к Сане», «отвяжи Парасюху», «отвяжи Саню»;
- человек: «я» → кто пишет; иначе сначала участники беседы, потом все люди (`POST /api/bot/people`: имя,
  в т. ч. в падеже — «Сане» = «Саня», точный логин, EBLID); несколько подходящих — бот переспрашивает с
  вариантами (имя и EBLID), уточнение понимает без цитирования;
- персонаж: по списку известных серверу игры (нормализатор похожих букв, `nick.ts`), не нашёлся — список
  модели (она выберет точный ник или переспросит);
- ответ: «Привязал: Саня — **IiApaCiOxa** (Парасюха).»; перепривязка — «Раньше этот персонаж был за
  «Петя» — у него отвязал»; отвязка — «… больше ни за кем не числится (был за «Саня»)»;
- у владельца новая привязка не снимает прежних персонажей человека (их может быть несколько);
- не владелец — только себя, как раньше (новая привязка заменяет прежнюю, чужого персонажа не отобрать,
  владельцу — уведомление); привязать или отвязать другого — вежливый отказ; людей для него не ищем;
- старый сервер (нет `/api/bot/people`) — «не могу найти людей», про себя («это я») работает.

## Выкладка «бот — часть системы» (НЕ выложено; первая выкладка бота-участника — 2026-10-10)

Порядок важен: сначала backend (миграция и маршруты), потом бот.

1. Backend: `docker compose -f deploy/docker-compose.full.yml --env-file .env build backend worker maintenance`
   и `up -d backend worker maintenance` — `docker-entrypoint.sh` применит миграцию `20261010180000_system_bot`
   (`User.isBot`, `Message.isBot`: константный DEFAULT, без перезаписи таблиц).
2. Перевод существующего бота: сначала проверка, потом `--apply` (из контейнера backend или из корня с `.env`):
   `node dist/scripts/setupSystemBot.js --account-file /DATA/eblusha-plus/.env.bot-account` →
   `… --apply`. Ставит `isBot`, помечает его старые сообщения, удаляет контакты с ботом, выводит его из
   групп БЕЗ системных записей, а имеющиеся 1:1 человек↔бот делает «Чатами с Еблушей» этих людей
   (они их сами заводили — настройка для них «включена»).
3. Бот: `docker compose -f deploy/docker-compose.full.yml --env-file .env --profile bot up -d --build --no-deps --force-recreate eblusha-bot`
   (новый `BOT_REDIS_URL` в compose; `--no-deps` — не трогать backend).
4. Клиенты (веб, ПК-натив, Android, iOS) — по `docs/bot-system.md`; старые клиенты не ломаются: сообщения
   бота для них — обычные сообщения от «Еблуша».

Учётка и ключ — как в первой выкладке:
- `TS_NODE_TRANSPILE_ONLY=1 node -r ts-node/register src/scripts/seedBotUser.ts --account-file /DATA/eblusha-plus/.env.bot-account --owner-username <логин владельца>`
  (создаёт `eblusha_bot` с `isBot`, пароль генерируется и не печатается).
- Владелец кладёт `ANTHROPIC_API_KEY=…` в `/DATA/eblusha-plus/.env.bot` (600); для ключа `sk-ant-usr…`
  там же нужен `ANTHROPIC_WORKSPACE_ID=wrkspc_…`. Если ключ не принят (в журнале `llm.probe_failed` и
  `llm.disabled`), бот работает без модели: команды, привязка ников, 👍, а на вопросы честно отвечает
  «мозги ещё не подключены». После правки `.env.bot` — шаг 3 с `--force-recreate` (`docker restart`
  окружение из env-файлов НЕ перечитывает).
- Valheim: токен канала мода должен существовать до запуска бота (compose его монтирует и без файла
  не стартует): `f=/DATA/valheim/config/bepinex/webmap-bot.token; [ -f $f ] || (umask 077; openssl rand -hex 32 > $f; chown 1000:1000 $f)`.
  Помощник для команд владельца — `bot/ops/README.md`.
- Владельцу: включить себе «Чат с Еблушей» в настройках. Игрокам — привязать ник: «Еблуша, мой ник в игре …».
